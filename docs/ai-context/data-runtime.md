# Данные и среда выполнения

## Конфигурация

- Конфигурация сервера и конфигурация Vite читают `.env` из корня репозитория. Отправная точка `.env.example`. Отдельные файлы окружения по приложениям не создавать.
- Нативному запуску нужны доступные PostgreSQL и Redis по значениям `DATABASE_URL` и `REDIS_URL`. Сервер слушает `PORT`, по умолчанию 3000. Vite проксирует API, Socket.IO и коллаборацию на `APP_URL`.
- `docker-compose.yml` поднимает приложение, PostgreSQL с pgvector, Redis, Gotenberg, а также внутренние сервисы `tessera-hub`, `tessera-drawio` и `tessera-minio`. Имена всех сервисов и томов несут префикс проекта. Продакшен использует образ из `Dockerfile`, который собирает весь монорепозиторий до установки продакшен-зависимостей.

## База и миграции

- В том же кластере PostgreSQL живет вторая база `tessera_hub` для внутреннего сервиса. Она создается скриптом `deploy/postgres-init/01-hub-database.sh` при первичной инициализации кластера и мигрируется отдельно, через Alembic внутри `services/hub`.
- Хранение в PostgreSQL через Kysely, не через Prisma. `DatabaseModule` использует `CamelCasePlugin`, типы базы лежат в `apps/server/src/database/types/`.
- Миграции это упорядоченные файлы TypeScript в `apps/server/src/database/migrations/`. Создавать и применять их скриптами `migration:create`, `migration:up`, `migration:down` и `migration:redo` пакета `server`.
- Разработка не применяет миграции автоматически. Запуск в продакшене вызывает `MigrationService.migrateToLatest()`.
- `apps/server/src/database/types/db.d.ts` генерируется командой `pnpm --filter server migration:codegen`, которая читает базу по корневому `.env`. Руками файл не править.

## Сервисы времени выполнения

- Redis обслуживает кеш, BullMQ, адаптер Socket.IO и часть коллаборации. Изменение возможности реального времени может затронуть `collaboration`, `ws`, кеш и фронтенд одновременно.
- Хранилище выбирается переменной `STORAGE_DRIVER` со значениями `local`, `s3` или `azure`. Обращения к файлам держать внутри интеграции хранилища и сохранять контракты загрузки и выгрузки.
- Почта работает через SMTP или Postmark. Экспорт PDF использует Gotenberg, когда он настроен. Поиск, ИИ, телеметрия и биллинг опциональны и управляются переменными окружения.
- `CLOUD`, `SUBDOMAIN_HOST`, биллинг и лицензирование меняют поведение при нескольких рабочих пространствах. При изменении контекста рабочего пространства и возможностей в `ee` проверять оба режима.
