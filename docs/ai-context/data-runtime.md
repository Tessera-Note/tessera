# Данные и время выполнения

## База

PostgreSQL с pgvector (образ `pgvector/pgvector:pg18`). Доступ через SQLAlchemy 2.0 в асинхронном режиме, драйвер asyncpg.

- модели `apps/api/tessera_api/infrastructure/models.py`
- запросы `apps/api/tessera_api/infrastructure/repositories.py`
- подключение и сессия `apps/api/tessera_api/infrastructure/database.py`

В базе змеиный регистр, наружу верблюжий. Преобразование делает слой DTO, а не запрос.

Ленивая загрузка связи в асинхронной сессии отвечает отказом. Связь, к которой обратятся после запроса, загружается через `selectinload`.

## Схема

Схема объявляется целиком и применяется Atlas. Файлов миграций в коде нет.

| Файл | Роль |
| --- | --- |
| `apps/api/schema/schema.hcl` | источник истины, около 3800 строк |
| `apps/api/schema/baseline.sql` | снимок для чистой базы, руками не правится |
| `apps/api/schema/after-atlas.sql` | доводка после Atlas, руками не правится |

Раскатка идёт тремя шагами состава, порядок обязателен: расширения и функции, затем таблицы Atlas, затем триггеры и индексы с сортировкой `C`. Триггеры ссылаются на таблицы, а функции нужны до Atlas, иначе не построятся умолчания первичных ключей.

Четыре индекса по ключу порядка исключены из ведения Atlas списком `--exclude`: свободная редакция Atlas не видит `COLLATE`, и он удалял бы их при каждом подъёме. Подробности и замеры в `.claude/skills/schema-changes/SKILL.md`.

Вторая версия подключается к той же базе, что и первая, и схему не пересоздаёт.

**Уникальность там, где удаление мягкое, ограничена условием.** Короткое имя
пространства и его вариант в нижнем регистре уникальны только среди живых
(`WHERE deleted_at IS NULL`). Без условия имя удалённого пространства
оставалось бы занятым навсегда, а попытка занять его отвечала пятисотым:
проверка в коде смотрит на признак удаления, а ограничение — нет. Уникальность
здесь именно индексом, а не ограничением таблицы: ограничение условия не
принимает.

Тот же приём стоит у личного пространства (`spaces_personal_creator_unique`).
Заводя уникальность на таблице с мягким удалением, условие добавлять сразу.

## Redis

Один экземпляр, три роли: кеш, очередь заданий arq, канал событий Socket.IO. Обвязка в `infrastructure/cache.py`, `infrastructure/queue.py`, `infrastructure/realtime.py`.

## Хранилище

`infrastructure/storage.py`. Два исполнения: локальный каталог и хранилище, совместимое с S3. В составе поднят MinIO, адрес по умолчанию `http://tessera-v2-minio:9000`.

## Окружение

Читается один раз при сборке приложения, в `config.py`, 44 имени. Умолчания задаются там и только там: пустая строка приравнена к отсутствующему значению, потому что compose подставляет пустую строку переменным, которых нет в файле окружения, и без этого правила она перебивала бы умолчание.

Обязательны четыре: `APP_SECRET`, `POSTGRES_PASSWORD`, `MINIO_ROOT_PASSWORD`, `COLLAB_INTERNAL_TOKEN`. Полный разбор по группам в `STACK.md`.

## Проверки против настоящей базы

Часть проверок приложения работает против настоящей базы и без `DATABASE_URL` пропускается, ещё часть — против настоящего Redis и пропускается без `REDIS_URL` (сводка правок и ограничение частоты: `test_digest.py`, `test_throttle.py`). Пропуск виден в выводе как `skipped`, и зелёный прогон без любой из двух переменных не означает, что проверено всё. Полный прогон делается с обеими, и в итоге пропусков быть не должно; причины показывает `pytest -rs`.

Такие проверки идут в откатываемой транзакции и в базе ничего не оставляют. Причина, по которой они не на заглушках: настройка экземпляра пишет семь связанных записей, и внешние ключи между ними проверяет только база.
