# MCP

## Точка входа и аутентификация

- Модуль лежит в `apps/server/src/ee/mcp/`, регистрируется в `src/ee/ee.module.ts` и состоит из `McpController` и `McpService`.
- `GET /mcp` и `GET /api/mcp` отдают метаданные обнаружения без аутентификации. `POST` по тем же путям принимает запросы MCP и использует `JwtAuthGuard` вместе с `@SkipTransform()`, чтобы вернуть JSON-RPC без обычного HTTP-конверта.
- Guard принимает cookie `authToken` либо заголовок `Authorization: Bearer <API_KEY>`. Ключи API это JWT, привязанные к создавшему их пользователю и рабочему пространству. Отключенные пользователи, отозванные и просроченные ключи и несовпадающее рабочее пространство отклоняются в `JwtStrategy` и `ApiKeyService`.
- MCP выполняется от имени аутентифицированного пользователя и рабочего пространства, определенного guard. Инструменты обязаны сохранять этот контекст. Не принимать идентификатор рабочего пространства как способ сменить область запроса.

## Протокол

- `McpService.handleRpcRequest()` поддерживает `initialize`, `notifications/initialized`, `tools/list` и `tools/call`. Ресурсов, пакетной обработки и инициируемых сервером запросов нет.
- Согласуемые версии протокола: `2024-11-05`, `2025-03-26` и `2025-06-18`. Сервер возвращает запрошенную известную версию, а для неизвестной возвращает `2025-06-18`.
- `tools/call` возвращает результат текстовым содержимым в JSON. Ошибка инструмента отдается как `result.isError: true`, неизвестный метод как ошибка JSON-RPC `-32601`.
- Источник истины это `getToolsList()` в `mcp.service.ts`. Список в `apps/client/src/ee/ai/components/mcp-settings.tsx` это только краткая сводка, он может быть неполным.

## Что доступно

- Страницы и spaces: список, чтение, создание, обновление, перемещение, дублирование, восстановление, удаление, навигация по хлебным крошкам и обратным ссылкам, текстовый поиск.
- Содержимое рабочего пространства: комментарии, метки, избранное, история, шаблоны, вложения и экспорт одной страницы.
- Bases: создание, преобразование страниц, чтение и изменение схемы, свойств, строк и представлений. Bases это страницы и подчиняются авторизации страницы.
- Расширенный поиск: семантический поиск, переиндексация эмбеддингов и широкий поиск по страницам, bases, комментариям и вложениям.
- Список и схемы инструментов в `getPageToolsList`, `getBaseToolsList` и `getWorkspaceToolsList`. Выполнение в `callTool`, `callWorkspaceTool` и `callBaseTool`.

## Авторизация и ограничения

- Операции проверяют членство в space, CASL и `PageAccessService` до чтения и изменения содержимого. Страницы другого рабочего пространства выдаются как ненайденные, чтобы нельзя было перебирать идентификаторы.
- Доступ ограничен правами пользователя, которому принадлежит ключ API, а не особыми правами MCP. При добавлении инструментов не обходить проверки сервисов, CASL и доступа к странице.
- `get_comment` проверяет доступ к странице комментария перед его выдачей, следуя тому же образцу, что и остальные инструменты страниц.
- Эндпоинт MCP ограничен по частоте на пользователя. Не считать, что новый инструмент или маршрут окажется вне этого ограничения.
- Формат содержимого страницы по умолчанию Markdown. `get_page` дополнительно принимает HTML и JSON ProseMirror. Обновления страницы принимают Markdown и по умолчанию работают в режиме дописывания.
- Загрузка вложения через MCP принимает не более 2 МиБ до кодирования в base64. Экспорт, дающий ZIP, например страница с потомками или вложениями, через MCP вернуть нельзя.

## Настройка и интерфейс

- Переключатель рабочего пространства это `settings.ai.mcp`, он меняется полем `mcpEnabled` в `UpdateWorkspaceDto`. Обновление требует лицензионной функции `mcp` и сохраняется через `WorkspaceRepo.updateAiSettings`.
- Экран ИИ в `apps/client/src/ee/ai/components/mcp-settings.tsx` показывает адрес `${APP_URL}/mcp`, включает и выключает переключатель и объясняет использование ключа API.
- `POST /mcp` проверяет `workspace.settings.ai.mcp` в контроллере и отвечает 403 через `ForbiddenException`, когда переключатель выключен или никогда не задавался. Информационный `GET /mcp` остается публичным и переключатель не читает.

## Изменения и тесты

- Добавляя инструмент, обновить и его схему в `getToolsList()`, и выполнение в нужном диспетчере. Применить границы рабочего пространства и те же проверки прав, что и у соответствующей HTTP-возможности.
- Меняя совместимость протокола, сохранить три согласуемые версии либо согласованно обновить тесты и документацию для клиентов.
- Покрывать контракт тестами `apps/server/src/ee/mcp/mcp.service.spec.ts` и `mcp.controller.spec.ts`, запуск `pnpm --filter server test -- ee/mcp`.
