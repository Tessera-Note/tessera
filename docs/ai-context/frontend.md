# Фронтенд

## Запуск и маршруты

- Точка входа `apps/client/src/main.tsx`. Он ставит `BrowserRouter`, Mantine, модальные окна, уведомления, React Query, Helmet, PostHog и i18n до отрисовки `App`.
- `apps/client/src/App.tsx` это карта маршрутов. Страницы лежат в `src/pages`, глобальный layout и layout публичного шара группируют приватные и публичные маршруты. Страницы маршрутов подключаются через `React.lazy` с одной общей границей `Suspense`, а layout и инфраструктура маршрутизации остаются загружаемыми сразу.
- Внутри `FullEditor` компонент `PageEditor` на Yjs и Hocuspocus рисуется только для правки или встроенных комментариев, которым нужны относительные выделения Yjs. Читатели без этих прав получают `ReadonlyPageEditor` без соединения коллаборации.
- `FullEditor`, модальное окно истории, `PageEditor` и `ReadonlyPageEditor` на странице шара импортируются статически, а не через `React.lazy`. Ленивая загрузка здесь неработоспособна: в production-сборке граница `Suspense`, которая монтируется вместе со страницей, после разрешения чанка не получает повторную попытку и навсегда остается в fallback. Страница показывала «Loading page content», а страница шара выглядела пустой. В dev-сервере дефект не воспроизводится. Дробление бандла не пострадало, код уезжает в чанк маршрута. Ленивые компоненты, которые монтируются по действию пользователя (`emoji-picker`, `MermaidView` в блоке кода, представление Excalidraw), работают штатно, их не трогать.
- Алиас `@/` указывает на `apps/client/src` и объявлен в TypeScript, Vite и Vitest. Использовать его для импортов внутри приложения, следуя путям, уже принятым в изменяемой области.

## Организация по фичам

- Переиспользуемый код домена лежит в `src/features/<домен>/`, обычно разделенный на `types`, `services`, `queries`, `components` и, при необходимости, `hooks`, `atoms`, `utils` или вложенные фичи.
- Страницы собирают фичи и layout. Не переносить правила доступа к HTTP и кеш в компоненты страницы, если у фичи уже есть слой сервисов и запросов.
- `src/ee` содержит экраны и возможности, зависящие от облака и лицензии. Флаги окружения читаются через `src/lib/config.ts`.

## HTTP, кеш и состояние

- `src/lib/api-client.ts` создает Axios с `baseURL: "/api"` и `withCredentials: true`. Интерцептор разворачивает конверт сервера, эндпоинты экспорта сохраняют полный ответ, чтобы был доступ к заголовкам и бинарным данным.
- Сервисы это небольшие типизированные функции, вызывающие `api`, как правило через `POST` на каждое действие, и возвращающие `req.data`. Для загрузки файлов используется `FormData` и `multipart/form-data`, как в сервисах страниц и вложений.
- Хуки в `queries/` отвечают за ключи запросов, `enabled`, курсорную пагинацию, инвалидацию и обновление кеша, обратную связь по мутациям. `queryClient` экспортируется из `src/main.tsx`.
- Глобальные значения React Query по умолчанию: без повторов запроса, без перезапроса при фокусе и монтировании, `staleTime` пять минут. Переопределять только по конкретной причине.
- Jotai отвечает за разделяемое локальное состояние, например дерево и сокет. Не использовать кеш React Query как замену состоянию взаимодействия.

## Интерфейс и язык

- Визуальная библиотека Mantine, тема в `src/theme.ts`. Использовать ее существующие провайдеры, модальные окна и уведомления.
- Формы обычно на Mantine Form со схемами Zod через `mantine-form-zod-resolver`.
- Видимые тексты проходят через `useTranslation` и i18next, как в соседних компонентах. Ошибки мутаций обычно показываются через `notifications.show`.
- Новая строка заводится в `apps/client/public/locales/en-US/translation.json`, даже если совпадает с ключом: источник для Crowdin именно он, и без записи строка не переводится ни на один язык. Правила словарей закреплены проверкой `apps/client/src/locales.test.ts`.
- Множественное число только суффиксами i18next `_one`, `_few`, `_many`, `_other`. Синтаксис ICU применять нельзя: плагина `i18next-icu` в проекте нет, а новая зависимость в рантайме запрещена, поэтому такое значение выводится буквально вместе со скобками. Русскому и украинскому нужны все четыре формы, иначе `count=3` и `count=7` падают на базовый ключ.
- `src/features/websocket` связывает обновления реального времени с кешем и состоянием клиента. Изменения в дереве, страницах или коллаборации должны учитывать и поток событий, а не только HTTP-запрос.

## Дерево страниц и структурное разделение React Query

- Событие `refetchRootTreeNodeEvent` (шлет `WsService.publishPreparedTreeRefresh`) обрабатывают **два** хука: `use-tree-socket.ts` вычищает узлы пространства из `treeDataAtom`, `use-query-subscription.ts` перезапрашивает `root-sidebar-pages`. Заполнение обратно делает эффект в `space-tree.tsx`.
- Эффект сторожил `pagesData` **по ссылке**. React Query применяет структурное разделение: если перезапрос вернул те же данные, ссылка не меняется, эффект не срабатывает, и вычищенное дерево не восстанавливается. Так вся навигация по пространству пропадала до перезагрузки от переименования **дочерней** страницы, корневой список которой не менялся, — например встроенной базы.
- Починено счетчиком `treeRefreshTokenAtom`: обработчик события бампает его вместе с очисткой, эффект держит его в зависимостях. Восстановление стало **явным действием**, не побочным эффектом смены ссылки.
- **Отключать структурное разделение ради этого нельзя**: те же данные читают и другие потребители, и отключение ударит по всем. Любая будущая связка «вычистить и перезапросить» обязана нести собственный явный признак перезаполнения.

## Пользовательские строки и словари

Правило прежнее: пользовательские тексты только через i18next, ключом служит
английская фраза. Но до `t(...)` строка доходит не всегда, и проверка
`apps/client/src/locales.test.ts` закрывает три способа ее обойти.

**Схемы проверки форм.** Схемы zod объявляются на уровне модуля, где хук
перевода вызвать нельзя. Переводится результат: формы подключают
`i18nZodResolver` из `apps/client/src/lib/zod-i18n.ts` вместо `zod4Resolver`, и
он пропускает готовые сообщения через словарь. В самих схемах сообщения
остаются английскими фразами, они же ключи. Незаведенное сообщение
возвращается как есть, так проходят встроенные тексты zod.

**Справочники строк.** Поля `message`, `label`, `title`, `description` в
справочниках (меню вставки, метки журнала аудита, предупреждения о смене типа
свойства) переводит потребитель на месте показа, вызывая `t(переменная)`.
Литерал такого вида проверке «каждый ключ из кода заведен в источнике» не
виден, поэтому есть отдельная проверка на сами литералы. Имя собственное,
название формата или языка заводится в `en-US` тождественно.

**Всплывающие уведомления.** Текст `notifications.show({ message })` заведомо
пользовательский, литерал там запрещен отдельной проверкой.

Что этими проверками не закрыто: ключ, собранный подстановкой (`t(\`Export
${type}\`)`), не виден ни одной из них. Такие места переписываются на явные
варианты.
