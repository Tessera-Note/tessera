# Бекенд

## Запуск и HTTP

- Сервер это NestJS поверх Fastify. `apps/server/src/main.ts` применяет глобальный префикс `/api`, кроме явно перечисленных публичных маршрутов, и регистрирует multipart, cookies, IP и адаптер Redis для Socket.IO.
- Глобальная валидация через `ValidationPipe` с `whitelist`, `transform` и `stopAtFirstError`. DTO это классы с `class-validator`, при необходимости с `class-transformer`.
- `TransformHttpResponseInterceptor` оборачивает ответы JSON в `{ data, success: true, status }`. Эндпоинты, которым нужно вернуть нативный HTTP-ответ, используют `@SkipTransform()`. Основной такой случай это экспорт.
- Лимит тела HTTP-запроса 10 МБ. Изменения загрузки файлов должны учитывать и его, и настраиваемые лимиты размера файлов.

## Модули и возможности

- `AppModule` собирает инфраструктуру. `CoreModule` регистрирует бизнес-модули и применяет `DomainMiddleware` и `AuditContextMiddleware` к маршрутам с явными исключениями для установки, проверки живости и вебхука Stripe.
- Типовая возможность состоит из `*.module.ts`, контроллера, DTO, сервиса и репозитория. Модули объявляют импорты, провайдеры и экспорты явно.
- Контроллеры принимают HTTP, DTO и контекст аутентификации. Сервисы координируют авторизацию, транзакции, события, очереди, хранилище и коллаборацию. Репозитории инкапсулируют запросы Kysely. Часть контроллеров обращается к репозиториям и сервисам доступа напрямую, когда случай требует конкретного чтения или проверки прав.
- Новый бизнес-модуль регистрируется в `apps/server/src/core/core.module.ts`, инфраструктура приложения в `apps/server/src/app.module.ts`.

## Аутентификация, рабочее пространство и авторизация

- Защищенные маршруты используют `JwtAuthGuard`, исключения открываются через `@Public()`. Действующего пользователя и рабочее пространство брать через `@AuthUser()` и `@AuthWorkspace()`, а не читать запрос вручную.
- `DomainMiddleware` кладет в запрос `workspaceId` и `workspace`: в self-hosted берется первое рабочее пространство, в облаке оно определяется по поддомену. Pre-handler в `main.ts` отклоняет маршруты API без рабочего пространства, кроме явно исключенных.
- Доменная авторизация построена на CASL и сервисах доступа, особенно для страниц и spaces. Возвращать подходящие исключения Nest (`BadRequestException`, `ForbiddenException`, `NotFoundException`), а не собственные форматы ошибок.
- Вход использует HTTP-only cookie `authToken`. Клиент отправляет учетные данные во всех вызовах API.

## Данные и интеграции

- `DatabaseModule` глобальный и предоставляет репозитории Kysely. Сервисы могут внедрить репозиторий либо `KyselyDB` через `@InjectKysely()` для согласованных транзакций.
- В репозиториях сосредоточены типизированные запросы, пагинация и запись. В сервисах бизнес-правила и внешние эффекты. Сохранять это разделение в новом коде.
- `src/integrations` содержит границы инфраструктуры. Не связывать возможности из `core` напрямую с деталями хранилища, почты, Redis или очередей, если уже есть модуль интеграции.
- `src/ee` это обычный каталог репозитория, он подгружается динамически из `AppModule`. При `CLOUD=true` отсутствие `EeModule` завершает приложение. Не делать импорты EE обязательными, не сохранив это поведение.
- MCP это модуль EE с контрактом JSON-RPC и собственной авторизацией. Перед правкой прочитать `docs/ai-context/mcp.md`.

## Отказы и письма

- Пользовательский отказ бросается помощником из `common/errors/app-error.ts`, а не текстом: наружу уходит устойчивый код, он же служит ключом перевода на клиенте. Текст в каталоге английский и запасной, он попадает в журнал и в ответ для читающих API напрямую. Новый код обязан появиться и в `apps/client/public/locales/en-US`, иначе человек увидит английский текст молча; это закреплено проверкой `apps/client/src/locales.test.ts`.
- Клиент не ветвится по тексту сообщения сервера. Опознавать отказ надо по коду: текст переводится, и сравнение по нему ломает переход молча.
- Письма собираются на языке получателя из `integrations/transactional/mail-text.ts`. Тема и шаблон строятся внутри `NotificationService.queueEmail`, которому передается функция от локали: язык известен только после чтения записи получателя.
