# Паттерны кода

## Сервер

- Входящие HTTP-данные описывать как DTO с декларативной валидацией. Контроллер держит маршруты, статусы, guard и извлечение контекста, бизнес-правила живут в сервисах.
- Для аутентифицированных эндпоинтов использовать `JwtAuthGuard`, `@AuthUser()` и `@AuthWorkspace()`, для публичных исключений `@Public()`. Не повторять чтение рабочего пространства, которое уже сделал middleware.
- Для доменных сбоев использовать исключения Nest. Не возвращать самодельные объекты ошибок: клиент и фильтры Nest уже обрабатывают HTTP-ответы.
- Запросы Kysely и пагинацию размещать в репозиториях. Сервисы координируют несколько репозиториев и внешние эффекты, для атомарной операции использовать транзакцию.
- Добавлять модуль, контроллер, провайдер и экспорт только там, где есть явная зависимость. Бизнес-модули регистрировать в `CoreModule`, инфраструктуру в `AppModule`.

## Клиент

- Для возможности с обращением к API начинать с `features/<домен>/types`, затем `services` и `queries`. Компоненты используют хуки, а не вызывают Axios напрямую.
- Сервисы возвращают типизированные данные и оставляют ключи запросов, инвалидацию, состояние мутации и уведомления хукам TanStack Query.
- Определять стабильные ключи запросов и обновлять или инвалидировать все кеши, затронутые мутацией. Страницы могут кешироваться и по `id`, и по `slugId`, при изменении этого потока сохранять оба.
- Использовать Jotai для состояния интерфейса и локальной синхронизации. Для совместных обновлений проверять хуки WebSocket и обновление кеша, а не только вызов REST.
- Переиспользовать компоненты Mantine и существующие переводы. Не вводить видимый текст без i18n там, где область уже использует `useTranslation`.

## Импорты, стиль и тесты

- Клиент использует алиас `@/`, сервер использует `@tessera/db/*`, `@tessera/transactional/*` и `@tessera/ee/*`. Сохранять стиль импортов того каталога, который правишь.
- Единого стиля кавычек на клиенте нет. Не делать чисто косметических изменений в файлах, не относящихся к задаче. Автоматическое форматирование клиента после правки намеренно отключено в `.claude/hooks/post-edit.sh` именно поэтому.
- Юнит-тесты сервера лежат рядом с кодом как `*.spec.ts`. Использовать типизированные заглушки и проверять делегирование, исключения и наблюдаемые эффекты. Сквозные тесты используют отдельную конфигурацию Jest и Supertest.
- Тесты клиента написаны на Vitest в jsdom. Для чистой логики предпочитать маленькие фикстуры и граничные случаи, внешние зависимости подменять через `vi.mock`.
