# Обзор системы

## Продукт и границы

Это совместная вики: рабочие пространства содержат spaces, а spaces содержат иерархические страницы с правами, комментариями, вложениями, историей, поиском и совместным редактированием в реальном времени. Основной код лежит в двух приложениях и двух общих пакетах.

| Область | Ответственность | Основная точка входа |
| --- | --- | --- |
| `apps/client` | SPA на React, которую видит пользователь | `src/main.tsx`, маршруты в `src/App.tsx` |
| `apps/server` | HTTP API, WebSocket, коллаборация, фоновые задачи и отдача приложения | `src/main.ts`, композиция в `src/app.module.ts` |
| `packages/editor-ext` | Общие расширения редактора | `src/index.ts` |
| `packages/base-formula` | Общие формулы с отдельными входами для клиента и сервера | `src/index.client.ts`, `src/index.server.ts` |

## Основной поток

1. Браузер запускает SPA из `apps/client/src/main.tsx`, где ставятся провайдеры Mantine, React Query, модальных окон, уведомлений, i18n и маршрутизации.
2. `apps/client/src/App.tsx` выбирает страницы и layout через React Router. Вызовы HTTP идут на `/api`, в разработке Vite проксирует их на `APP_URL`.
3. `apps/server/src/main.ts` поднимает Nest на Fastify, Redis для WebSocket, multipart и cookies, валидацию и глобальный префикс `/api`.
4. `AppModule` регистрирует домен, данные, Redis, очереди, хранилище, импорт и экспорт, коллаборацию, телеметрию и бизнес-модули. `CoreModule` собирает центральные возможности.
5. Сервисы координируют бизнес-правила, репозитории Kysely пишут в PostgreSQL. Redis используется кешем, очередями и инфраструктурой коллаборации и WebSocket.

## Значимые границы

- `apps/server/src/core`: бизнес-возможности, такие как аутентификация, рабочее пространство, space, страница, комментарии, группы, поиск и вложения.
- `apps/server/src/integrations`: адаптеры окружения, хранилища, почты, очередей, Redis, экспорта, импорта, проверки живости и безопасности.
- `apps/server/src/database`: глобальный модуль Kysely, репозитории, слушатели, пагинация, миграции и типы базы.
- `apps/server/src/collaboration` и `apps/server/src/ws`: коллаборация и обмен в реальном времени. Не рассматривать их как обычные HTTP-эндпоинты.
- `apps/client/src/pages`: композиция экранов по маршруту. `apps/client/src/features`: переиспользуемый код, сгруппированный по домену.
- `apps/*/src/ee`: возможности, включаемые условно. При работе с ними сохранять границы облака и лицензирования. Каталог `apps/server/src/ee` это обычный каталог репозитория, сторонних сабмодулей в проекте нет.

## Источники истины

- Скрипты и инструменты: `package.json`, манифесты каждого приложения и пакета, `nx.json` и workflow в `.github/workflows/` при их наличии в чекауте.
- Маршруты и запуск: `apps/client/src/App.tsx`, `apps/server/src/main.ts` и `apps/server/src/app.module.ts`.
- Контекст времени выполнения: `.env.example`, `docker-compose.yml`, `Dockerfile` и `docs/deployment.md`.
- Стек, версии и команды: `STACK.md` в корне репозитория.
