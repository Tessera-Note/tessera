# Что не переносится сменой языка

Главный документ. По каждому пункту: в чем препятствие, варианты, цена,
рекомендация. Числа из `00-inventory.md`.

Общее правило оценки ниже: «переписать» означает написать заново с проверкой
на настоящих данных, а не перевести построчно.

## 1. Совместное редактирование

**Что есть.** Hocuspocus поверх Yjs, 2 480 строк в `apps/server/src/collaboration`:
хранение состояния документа, синхронизация через Redis, аутентификация
подключения, ws `/collab`. Клиентская сторона — `y-prosemirror` в редакторе.

**Препятствие.** Hocuspocus существует только под Node. `pycrdt` реализует CRDT
Yjs, но это привязка к Rust-библиотеке `yrs`, и серверного протокола Hocuspocus
у нее нет: синхронизация, awareness, аутентификация и хранение пишутся заново.

**Варианты.**

| Вариант | Цена | Что теряется |
|---|---|---|
| Оставить Hocuspocus сервисом на Node в compose | ~0 переписывания, +1 сервис и +1 язык в развертывании | Ничего в функциях. Продукт перестает быть одноязычным |
| Переписать на `pycrdt` со своим ws-слоем | 2 480 строк заново плюс протокол, ~3–4 недели с проверкой на живом многопользовательском редактировании | Зрелость. Ошибки схождения документов проявляются под нагрузкой и не ловятся модульными тестами |

**Рекомендация: оставить Hocuspocus отдельным сервисом на Node.** Совместное
редактирование это узел, где ошибка означает потерю текста у человека прямо во
время набора. Менять зрелую реализацию на собственную ради единообразия языка
несоразмерно риску. Сервис уже изолирован своим ws-каналом, его граница
проходит там же, где сейчас.

## 2. Преобразование содержимого страниц

**Что есть.** `TiptapTransformer`, сборка `Y.Doc` из JSON и обратно, схема узлов
редактора. От этого зависят импорт, экспорт, история версий, полнотекстовый
поиск и индексация для эмбеддингов.

**Препятствие.** Схема узлов описана расширениями Tiptap на TypeScript
(13 614 строк в `packages/editor-ext`). Питон не может собрать `Y.Doc` по этой
схеме, не имея самой схемы.

**Варианты.**

| Вариант | Цена | Что теряется |
|---|---|---|
| Вынести преобразование в тот же Node-сервис, что и Hocuspocus, дать ему HTTP-эндпоинт | ~200 строк обвязки | Сетевой вызов на каждом преобразовании |
| Описать схему узлов повторно на Python | 13 614 строк эквивалента, и две схемы, которые обязаны совпадать | Расхождение схем это порча содержимого, и проявится оно не сразу |

**Рекомендация: первый вариант.** Схема узлов обязана быть одна. Две
реализации одной схемы это класс ошибок, который мы сегодня закрывали весь день
в другом месте: два описания одного и того же расходятся.

## 3. Экспорт DOCX

**Что есть.** Собственный сериализатор ProseMirror в Word, 1 435 строк в
`packages/editor-ext/src/lib/prosemirror-docx`, форк библиотеки под Node.

**Препятствие.** Питоновского эквивалента нет. `python-docx` умеет собирать
документ, но отображение узлов ProseMirror в его объекты пишется заново, и это
и есть основная часть тех 1 435 строк.

**Варианты.**

| Вариант | Цена | Что теряется |
|---|---|---|
| Оставить в Node-сервисе преобразования | ~50 строк обвязки | Ничего |
| Переписать на `python-docx` | 1 435 строк заново, ~2 недели, плюс сверка вывода на настоящих документах | Точность верстки. Расхождения видны только глазами в Word |

**Рекомендация: оставить в Node-сервисе.** Он к этому моменту уже существует
ради пунктов 1 и 2, и добавление к нему экспорта не заводит нового узла.

## 4. Импорт

**Что есть.** 3 659 строк. `mammoth` для DOCX, `@docmost/pdf-inspector` для PDF,
`cheerio` для Confluence.

**Препятствие.** Все три под Node. Питоновские аналоги есть: `python-docx` или
`mammoth`-порт, `pypdf`/`pdfplumber`, `beautifulsoup4`/`lxml`.

**Здесь мерить, а не предполагать.** Качество разбора это не свойство языка, а
свойство библиотеки на конкретных файлах. У нас есть настоящие выгрузки Google
Docs и Confluence, на которых текущий импорт проверен.

**Вариант решения.** До выбора провести замер: прогнать один и тот же набор
файлов через нынешний импорт и через питоновский прототип, сравнить полученные
документы. Решение принимать по результату замера, а не по обещаниям
библиотек. Стоимость замера ~3 дня, стоимость ошибки без замера — молчаливая
потеря содержимого при импорте.

**Рекомендация: замерить, и при равном качестве переносить на Python.** Импорт
не в горячем пути и его отказ виден сразу, в отличие от совместного
редактирования.

## 5. SCIM

**Что есть.** 2 457 строк, библиотека `scimmy` плюс наложенный патч.

**Препятствие.** Готового эквивалента в Python нет. Но SCIM это протокол
поверх HTTP с описанной в RFC 7643 и 7644 схемой, а не сложный алгоритм: у нас
уже написаны ресурсы Users и Groups, фильтр, разбор PATCH и формат ошибок.
`scimmy` дает схемы и разбор фильтров, остальное наше.

**Варианты.**

| Вариант | Цена |
|---|---|
| Переписать на Litestar вручную | 2 457 строк, из них ~600 это разбор фильтра SCIM и схемы. ~3 недели |
| Оставить в Node-сервисе | Node-сервис становится не «редакторским», а свалкой |

**Рекомендация: переписать на Python.** Поверхность узкая и полностью
покрывается тестами против настоящего провайдера. Держать ради нее второй
рантайм неоправданно.

## 6. Агент и инструменты

**Что есть.** 2 299 строк чата ИИ плюс 3 281 строка MCP, 65 инструментов, мост
между ними, разметка по обратимости и план с подтверждением.

**Препятствие.** Vercel AI SDK под Node. В Python есть `pydantic-ai` и прямые
SDK провайдеров, tool-calling у обоих есть.

**Важно.** Сами 65 инструментов это не обвязка ИИ, а операции над вики: они
переписываются вместе с бэкендом в любом случае и в блокеры не входят. Заново
пишется только слой агента: определения инструментов, цикл шагов, разбор
потока.

**Оценка.** ~1 500 строк слоя агента, остальное следует за переписыванием
доменных сервисов. ~2 недели.

**Рекомендация: переписать на Python.** Замена SDK здесь дешевая, а поведение
проверяется живым разговором, как сегодня.

## 7. Очереди

**Что есть.** BullMQ, 48 имен задач, 8 процессоров.

**Препятствие.** Формат задач BullMQ в Redis свой. Питоновская очередь
(`arq`, `taskiq`, `dramatiq`) его не читает: **задачи, лежащие в Redis на момент
переключения, будут потеряны**.

**Варианты.**

| Вариант | Цена |
|---|---|
| Дождаться опустошения очередей и переключиться | Окно простоя записи, минуты. Требует остановки постановки новых задач |
| Написать читатель формата BullMQ на Python | Неоправданно: формат недокументирован и меняется |
| Оставить BullMQ в Node-сервисе | Третья роль у сервиса, который заводился ради редактора |

**Рекомендация: первый вариант, с явной процедурой.** Перед переключением
остановить постановку, дождаться пустых очередей, снять слепок Redis, включить
новый рантайм. Это обычная процедура перехода, ее надо описать и отрепетировать
на стенде, а не изобретать в момент переключения.

## 8. Редактор на фронте

**Что есть.** 18 223 строки в `features/editor`, **38 представлений узлов,
написанных как компоненты React**, плюс 13 614 строк общих расширений.

**Препятствие.** Tiptap поддерживает Svelte, ядро переносится. Но представления
узлов — это React-компоненты, и они не портируются, а пишутся заново: таблицы,
диаграммы, вложения, встраивания, упоминания, комментарии на полях, колонки,
callout, математика, база как таблица.

**Это самая большая часть фронтенда.** По объему сопоставима со всем остальным
клиентом вместе.

**Оценка.** 38 представлений, от 50 до 900 строк каждое. Реалистично **8–12
недель** только на них, при условии, что поведение сверяется с текущим
редактором вручную: автоматических тестов на редактирование в проекте нет.

**Вариантов «дешевле» нет.** Единственный способ сократить — сузить набор
поддерживаемых узлов в v2 и вернуть остальные позже. Это продуктовое решение,
не техническое.

## 9. Библиотека интерфейса

**Что есть.** Mantine 9, **453 файла из 505 компонентов** используют ее.

**Препятствие.** Прямого аналога Mantine в Svelte нет. Ближайшие по охвату:
Skeleton (на Tailwind), Bits UI плюс собственная верстка, shadcn-svelte.

**Следствие.** Интерфейс v2 не будет выглядеть как нынешний. Это не побочный
эффект, это неизбежность: 453 файла завязаны на компоненты, поведение и темы
Mantine.

**Рекомендация: Bits UI плюс Tailwind 4.** Bits UI дает доступное поведение без
навязанного вида, Tailwind уже в целевом стеке. Skeleton навязывает свою
систему тем, и уходить с нее потом дороже.

**Цена.** Вся верстка клиента заново, 505 компонентов. **12–16 недель.**

## Сводка по блокерам

| Блокер | Рекомендация | Оценка |
|---|---|---|
| Совместное редактирование | Оставить в Node | 0 |
| Преобразование содержимого | Оставить в Node | ~1 неделя обвязки |
| Экспорт DOCX | Оставить в Node | ~2 дня |
| Импорт | Замерить, вероятно Python | 3 дня замера + 3 недели |
| SCIM | Python | 3 недели |
| Агент | Python | 2 недели |
| Очереди | Процедура перехода | 1 неделя, включая репетицию |
| Редактор на фронте | Заново | 8–12 недель |
| Библиотека интерфейса | Bits UI + Tailwind | 12–16 недель |

**Node из развертывания не уходит.** Первые три пункта означают, что в compose
остается сервис на Node: совместное редактирование, преобразование содержимого,
экспорт DOCX. Это надо принять как условие, а не как временную уступку.
