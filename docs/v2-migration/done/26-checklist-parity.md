## Как ведётся этот документ

Сделанный пункт помечается `[x]`, подробности переносятся в
`NN-краткое-имя.md` в этом же каталоге. Документ закрыт, когда не осталось ни одного `[ ]`.

Порядок пунктов — порядок работы и порядок важности. Первая группа — про
потерю вида содержимого, привезённого из v1; она идёт вперёд всего.

## 1. Отображения узлов редактора

В v1 своё отображение настроено у восемнадцати узлов, в v2 — у четырнадцати.
Это единственное место, где v2 теряет вид уже написанного.

- [x] `MathInline` и `MathBlock`. В v1 формула рисуется KaTeX
      (`math-inline.tsx`, `math-block.tsx`). В v2 KaTeX нет вовсе, и формула
      показывается сырым LaTeX. [Готово](15-math.md)
- [x] `Attachment`. В v1 карточка файла: значок, имя, размер, скачивание, ход
      загрузки (`attachment-view.tsx`, 173 строки). В v2 узел зарегистрирован,
      отображения нет. [Готово](16-attachment.md)
- [x] `CustomCodeBlock`. В v1 выбор языка и кнопка копирования
      (`code-block-view.tsx`, 105 строк). В v2 подсветка есть, выбора и
      копирования нет. [Готово](17-code-block.md)
- [x] Диаграмма Mermaid. Найдена при разборе предыдущего пункта: в v1 её рисует
      отображение блока кода, когда язык `mermaid` (`mermaid-view.tsx`). В v2
      блок «Диаграмма Mermaid» есть в перечне вставки, но заводит обычный блок
      кода — диаграмма не рисуется вовсе. [Готово](17-code-block.md)

## 2. Вход через Google

- [x] v1 держит четыре вида провайдера (`saml`, `oidc`, `google`, `ldap`) и
      маршруты `/api/sso/google/login` и `/api/sso/google/callback`. Сервер v2
      тип `google` знает (`sso_providers.py`), но входных маршрутов нет, а
      экран настроек предлагает три вида: провайдера можно завести и нельзя
      использовать. [Готово](18-google-sso.md)
- [x] Вход через провайдера с экрана входа. Найдено при разборе предыдущего
      пункта: на экране входа v2 нет ни одной кнопки провайдера. Сервер отдаёт
      их публично (`/api/workspace/public` возвращает `authProviders` и
      `enforceSso`), маршруты входа есть у всех четырёх протоколов, а войти
      через провайдера нельзя ни одним. В v1 это `sso-login.tsx`: кнопки,
      окно имени и пароля для LDAP, самостоятельный переход, когда провайдер
      единственный и вход через него обязателен, и предупреждение по
      `?error=sso`. [Готово](18-google-sso.md)

## 3. SCIM: описание схем

- [x] `GET /api/scim/Schemas` и `GET /api/scim/Schemas/{id}`. У v2 есть
      `ServiceProviderConfig` и `ResourceTypes`, все глаголы для `Users` и
      `Groups` на месте, описания схем нет. Эту точку опрашивают Okta и Entra
      при заведении приложения. [Готово](19-scim-schemas.md)

в v2 такого маршрута не было.

- [x] Подпись упоминания в v2 бралась из атрибута узла, замороженного при

## Что в этот список не входит

**Рассылка совместного редактирования между репликами.** Отложена осознанно и
записана в `12-deferred.md`: экземпляр один, ограничение вынесено
предупреждением в оба compose-состава.

**Облачные экраны и ограничение возможностей по лицензии** (`/create`,
`/select`, `/verify-email`, `billing`, `workspace/check-hostname`,
`workspace/entitlements`). Экземпляр держат у себя, во внешнюю службу лицензий
он не ходит, и все возможности включены — так прямо написано на экране
лицензии v2.

**Замены, а не пропажи.** `GlobalDragHandle`, `SlashCommand` и `EmojiCommand`
из v1 заменены своими реализациями v2 (`menus/DragHandle.svelte`,
`menus/suggest.svelte.ts`), и обратно их возвращать незачем.
