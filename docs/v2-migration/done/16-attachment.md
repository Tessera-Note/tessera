# 16. Карточка вложения

## Было

Узел `attachment` в v2 был зарегистрирован без отображения: файл, вложенный в
страницу, не показывался никак. В v1 это карточка со значком, именем,
размером, отметкой о попадании в поиск, кнопкой скачивания и — для PDF —
кнопкой встраивания (`attachment-view.tsx`, 173 строки).

## Сделано

`apps/web/src/lib/features/editor/views/AttachmentView.svelte`.

**Скачивание с проверкой до перехода.** Прямая ссылка на удалённое вложение
открывала бы в новой вкладке отказ сервера как есть; состояние проверяется
`resolveMediaErrorStatus` из общего пакета — тем же способом, что и у
остальных вложений, — и причина называется словами.

**Встраивание PDF заменяет узел целиком**, а не дописывает второй: встроенный
просмотр это другой узел схемы, а не другой вид того же вложения.

**Отметка «не найдётся поиском»** приходит с сервера. Правило разбора живёт
там: извлечение текста берёт обычный текст, Markdown, JSON, PDF и DOCX, а
картинка, архив и PDF из сканов не попадут в поиск никогда. Второй такой
список на клиенте разошёлся бы с первым.

`formatBytes` и `attachmentInfo` заведены в
`apps/web/src/lib/features/page/services/attachments.ts`. Счёт размера тот же,
что в v1, чтобы одна и та же страница показывала один и тот же размер.

### Два дефекта сервера, найденные при проверке

**Состояние разбора не отдавалось наружу.** Колонка `index_status` в базе
есть, а `/api/files/info` её не возвращал: карточке нечего было показывать.
Добавлено в ответ.

**Файл с нелатинским именем нельзя было скачать вовсе.** Имя ставилось в
`Content-Disposition` как есть, а заголовки кодируются latin-1 — выдача падала
с 500 на любом файле с кириллицей в имени. Имя пишется дважды: закодированным
обычным полем для старых клиентов и полем `filename*=UTF-8''` для остальных.
Точно так же это уже сделано в выгрузках (`api/exports.py`), то есть образец в
кодовой базе был, а до вложений не дошёл.

## Проверено

- Осмотром в браузере: настоящий файл `заметка.txt` загружен через
  `/api/files/upload`, карточка показывает имя и размер, кнопка скачивания
  открывает файл, заголовок ответа содержит оба поля имени.
- `AttachmentView.svelte.test.ts` (8): имя и размер, состояние загрузки,
  встраивание PDF только для PDF и только в правке, замена узла, а не дописка,
  отказ по пропавшему файлу, открытие живого, отметка о поиске с сервера.
- `test_attachments.py`: состояние разбора в ответе `info`, заголовок выдачи
  кодируется latin-1 и несёт `filename*`, вложенные типы показываются, а
  остальные сохраняются.
- Обе серверные проверки проверены внесением дефекта: снятие поля и возврат
  имени без кодирования роняют по одной проверке каждое.
