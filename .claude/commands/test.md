Прогони тесты.

## Что запускать

| Аргумент | Команда | Что покрывает |
|---|---|---|
| пусто | `pnpm --filter server test` и `pnpm --filter client test` | все юнит-тесты |
| `server` | `pnpm --filter server test` | Jest, `apps/server/src/**/*.spec.ts` |
| `client` | `pnpm --filter client test` | Vitest в jsdom |
| `e2e` | `pnpm --filter server test:e2e` | Supertest, `apps/server/test/*.e2e-spec.ts` |
| путь или подстрока | `pnpm --filter server test -- $1` либо `pnpm --filter client test -- $1` | точечный прогон |

Определить сторону по пути: `apps/server` это Jest, `apps/client` это Vitest.

## Что есть в проекте

30 серверных спеков, сосредоточены вокруг MCP, ИИ, шаблонов, bases, Socket.IO, поиска, сессий и прав на страницы. Два сквозных теста. Пять клиентских тестов. Покрытие точечное, отсутствие теста на соседний модуль это норма, а не поломка.

## Требования к e2e

Сквозным тестам нужны доступные PostgreSQL и Redis по значениям из корневого `.env`. Если их нет, тесты упадут на подключении. Это не считать регрессией кода, сказать об этом явно.

## После прогона

Показать число пройденных и упавших. По каждому упавшему дать файл, имя теста и суть ошибки.

Если тест падал и до изменений, показать это отдельно и не выдавать за результат задачи. Красных тестов в финальном отчете быть не должно.
