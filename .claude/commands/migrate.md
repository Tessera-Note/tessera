Работа с миграциями Kysely. Подробности паттерна в `.claude/skills/kysely-migrations/SKILL.md`.

## Действия

| Аргумент | Команда | Комментарий |
|---|---|---|
| `create <название>` | `pnpm --filter server migration:create <название>` | название в кебаб-кейсе, метка времени проставляется сама |
| `up` | `pnpm --filter server migration:up` | применить непримененные |
| `codegen` | `pnpm --filter server migration:codegen` | перегенерировать `apps/server/src/database/types/db.d.ts` из базы |
| `status` | показать содержимое `apps/server/src/database/migrations/`, отсортированное по имени | быстрый обзор |

## Заблокировано

`migration:down` и `migration:reset` заблокированы хуком `protect-bash.sh`, потому что теряют данные. Если откат действительно нужен, объяснить пользователю последствия и попросить выполнить вручную.

## Порядок для изменения схемы

1. `create` с осмысленным названием
2. заполнить `up` и обязательный `down` в созданном файле
3. `up` для применения
4. `codegen` для обновления типов
5. обновить сущности в `apps/server/src/database/types/`, если добавлена таблица
6. запустить агента `schema-reviewer`

## Требования к содержимому миграции

- существующие миграции не редактировать, даже при ошибке. Писать новую
- `down` обязателен и должен откатывать `up`
- первичный ключ `uuid` со значением по умолчанию `gen_uuid_v7()`, временные метки `timestamptz` со значением `now()`
- ссылку на рабочее пространство делать через `workspace_id` с `onDelete('cascade')`
- на колонку внешнего ключа, по которой идет выборка, ставить индекс
- `NOT NULL` в непустой таблице добавлять в три шага: колонка, заполнение, ограничение

## Замечания

В разработке миграции автоматически не применяются, в продакшене применяются при старте приложения. Поэтому непримененная локально миграция на проде выполнится сама, проверять ее надо до выкладки.

`codegen` подключается к базе по `DATABASE_URL` из корневого `.env`. Без работающей базы команда не отработает.
