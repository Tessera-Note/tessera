Проверь локализацию.

## Шаг 1. Валидность JSON

```
for l in de-DE en-US es-ES fr-FR it-IT ja-JP ko-KR nl-NL pt-BR ru-RU uk-UA zh-CN; do
  node -e "JSON.parse(require('fs').readFileSync('apps/client/public/locales/$l/translation.json','utf8')); console.log('$l ok')"
done
```

## Шаг 2. Количество ключей по локалям

```
for l in apps/client/public/locales/*/; do
  printf '%s %s\n' "$(basename "$l")" "$(grep -c '":' "$l/translation.json")"
done
```

Ориентир на момент настройки: `en-US` и `pt-BR` по 1338, `ru-RU` и `uk-UA` по 1291. Отставание не-английских локалей это норма, их наполняет Crowdin из `en-US`.

## Шаг 3. Глубокий анализ

Запустить агента `i18n-reviewer`. Он проверит:

- ключи, используемые в коде через `t()` и отсутствующие в `en-US`, это блокер
- захардкоженные пользовательские тексты в компонентах, где рядом уже есть `useTranslation`
- сломанную подстановку: переменная в значении не передана в код или наоборот
- одинарные скобки `{var}` вместо формата i18next `{{var}}`
- дубли одной фразы под разными ключами

## Шаг 4. Отчет

Показать результат агента пользователю. Сам ничего не переводить и не править не-английские словари: они перезаписываются при синхронизации Crowdin.

Недостающие ключи в `en-US` добавить, это единственный словарь, который правится вручную.
