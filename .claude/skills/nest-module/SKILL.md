# Серверный модуль

## Когда применять

Добавляется эндпоинт, новый модуль в `core` или `integrations`, меняется DTO, guard, проверка прав, ставится задача в очередь.

## Устройство

Nest 11 поверх Fastify. Глобальный префикс `/api`, исключения перечислены в `apps/server/src/main.ts`: `robots.txt`, страница публичного шара, `mcp`, `api/mcp`.

Типовой модуль это `<имя>.module.ts`, контроллер, папка `dto`, сервис, при необходимости репозиторий в `apps/server/src/database/repos`.

```ts
@Module({
  controllers: [LabelController],
  providers: [LabelService],
  exports: [LabelService],
})
export class LabelModule {}
```

Регистрация: бизнес-модуль в `apps/server/src/core/core.module.ts`, инфраструктурный в `apps/server/src/app.module.ts`. Лицензионный модуль в `apps/server/src/ee/ee.module.ts`, но каталог `ee` это git submodule на чужой репозиторий, править его нельзя.

## Разделение обязанностей

| Слой | Отвечает за | Не делает |
|---|---|---|
| контроллер | маршрут, статус, guard, DTO, извлечение пользователя и рабочего пространства | бизнес-правила, SQL |
| сервис | правила, транзакции, события, очереди, storage, коллаборация | прямой разбор запроса Fastify |
| репозиторий | типизированные запросы Kysely, пагинация | правила и внешние эффекты |

## Контроллер

```ts
@UseGuards(JwtAuthGuard)
@Controller('labels')
export class LabelController {
  constructor(private readonly labelService: LabelService) {}

  @HttpCode(HttpStatus.OK)
  @Post('/info')
  async getLabel(@Body() dto: LabelInfoDto, @AuthUser() user: User) {
    return this.labelService.getLabel(dto, user);
  }
}
```

Соглашения проекта

- действия оформлены как `POST` с телом, а не как REST по методам. Следовать соседним контроллерам
- пользователь и рабочее пространство берутся через `@AuthUser()` и `@AuthWorkspace()`. Читать их из запроса вручную не надо, их кладет `DomainMiddleware`
- защита по умолчанию через `JwtAuthGuard`. `@Public()` это изменение поверхности аутентификации, ставится осознанно и объясняется
- ошибки через исключения Nest: `BadRequestException`, `ForbiddenException`, `NotFoundException`. Свой формат ошибки не изобретать
- ответ автоматически оборачивается в `{ data, success, status }`. Нативный ответ (экспорт, JSON-RPC у MCP) требует `@SkipTransform()`
- страница чужого рабочего пространства отдается как «не найдено», а не как «нет доступа», чтобы нельзя было перебирать идентификаторы

## DTO

Классы с декораторами `class-validator`, при необходимости `class-transformer`. Глобальный `ValidationPipe` настроен с `whitelist`, `transform` и `stopAtFirstError`, поэтому непомеченные поля просто отбрасываются.

Числовые границы задавать явно. Образец в `apps/server/src/core/search/dto/search.dto.ts`: `limit` целое от 1 до 100, `offset` целое от 0, у подсказок `limit` до 25.

## Права

- права рабочего пространства и space через CASL, фабрики в `apps/server/src/core/casl`
- доступ к содержимому страницы только через `PageAccessService` либо предикат `PagePermissionRepo`. Членства в space недостаточно: нужен доступ ко всем ограниченным предкам, а ближайший ограниченный предок определяет право записи
- одно и то же правило обязано действовать в HTTP, в коллаборации, в списках, в уведомлениях, в событиях Socket.IO и в инструментах MCP. Добавил проверку в одном месте, проверь остальные

## Ограничение частоты

Глобального лимита на все эндпоинты нет. Отдельные лимиты настроены для аутентификации, чата ИИ, MCP и экспорта PDF. Новый эндпоинт в этих областях обязан получить тот же guard из `apps/server/src/integrations/throttle`.

## Очереди и события

Долгие и отложенные эффекты уходят в BullMQ, модуль очередей глобальный. Общие задачи получают три попытки с экспоненциальной задержкой, файловые задачи одну попытку с удалением записи после завершения.

Не переносить в HTTP-запрос то, что сейчас выполняется в очереди (история, упоминания, обратные ссылки, индексация ИИ, наблюдатели, уведомления), не оценив идемпотентность и задержку.

## Тесты

Юнит-тесты лежат рядом с кодом, `*.spec.ts`, окружение `node`, mock через типизированные заглушки. Проверять делегирование, исключения и наблюдаемые эффекты.

```
pnpm --filter server test -- <путь или подстрока>
pnpm --filter server test:e2e
```

Сквозные тесты в `apps/server/test/*.e2e-spec.ts` на Supertest, отдельный конфиг `jest-e2e.json`.

## Антипаттерны

- SQL или `db.selectFrom` внутри контроллера
- собственная резолюция рабочего пространства вместо `DomainMiddleware`
- возврат объекта ошибки вместо исключения Nest
- обязательный импорт из `ee` в коде вне `ee`. Модуль грузится динамически и может отсутствовать
- новый эндпоинт выдачи содержимого без прохода через проверку доступа к странице
- смешивание каналов: события дерева и уведомления идут через Socket.IO, содержимое документа через Hocuspocus на `/collab`
