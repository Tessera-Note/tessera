# Клиентская фича

## Когда применять

Добавляется компонент, страница, маршрут, вызов к серверу, хук запроса или мутации, обработка события реального времени.

## Порядок работы

Для фичи с обращением к серверу двигаться строго в этом порядке.

```
features/<домен>/types/<домен>.types.ts      описания данных
features/<домен>/services/<домен>-service.ts  функции над api
features/<домен>/queries/<домен>-query.ts     хуки TanStack Query
features/<домен>/components/*.tsx             интерфейс
```

Страница в `src/pages` только собирает фичи и layout. Правила доступа, кеш и HTTP в страницу не выносятся, если у фичи уже есть слой сервисов и запросов.

Компонент не вызывает `api` напрямую и не парсит ответы. Разбор данных живет в сервисе.

## Сервис

```ts
import api from "@/lib/api-client";
import { IPagination } from "@/lib/types.ts";
import { ILabel, IListLabelsParams } from "@/features/label/types/label.types.ts";

export async function getWorkspaceLabels(
  params: IListLabelsParams,
): Promise<IPagination<ILabel>> {
  const req = await api.post<IPagination<ILabel>>("/labels", params);
  return req.data;
}
```

- клиент axios в `src/lib/api-client.ts`, базовый путь `/api`, включен `withCredentials`
- интерцептор уже разворачивает конверт сервера. Возвращать `req.data`
- эндпоинты экспорта из списка исключений в интерцепторе возвращают полный ответ, чтобы был доступ к заголовкам и бинарным данным
- вызовы к серверу оформляются как `POST` с телом, следуя серверным контроллерам
- загрузка файлов через `FormData` и `multipart/form-data`
- ошибку не проглатывать, пусть всплывает в хук

## Хуки запросов

```ts
const WORKSPACE_LABELS_KEY = (query?: string) => ["workspace-labels", query ?? ""];

export function useWorkspaceLabelsQuery(query: string, enabled: boolean) {
  return useQuery({
    queryKey: WORKSPACE_LABELS_KEY(query),
    queryFn: () => getWorkspaceLabels({ type: "page", query, limit: 50 }),
    enabled,
    staleTime: 30 * 1000,
  });
}
```

- ключ запроса выносится в именованную функцию рядом с хуками, чтобы мутации инвалидировали тот же ключ
- глобальные значения по умолчанию: без повторов при ошибке, без перезапроса при фокусе и монтировании, `staleTime` пять минут. Переопределять только с конкретной причиной
- мутация обязана обновить или инвалидировать все затронутые кеши. Страница кешируется и по `id`, и по `slugId`, при изменении сохранять оба
- уведомления об ошибке мутации через `notifications.show` из Mantine, текст через `t()`
- `queryClient` экспортируется из `src/main.tsx`

## Состояние

- серверные данные в TanStack Query
- состояние интерфейса и локальная синхронизация в Jotai (дерево страниц, сокет, сайдбар)
- кеш запросов не использовать как хранилище состояния взаимодействия

Дерево страниц это особый случай. Мутация обязана согласованно сделать три вещи: обновить локальное состояние Jotai, вызвать REST и отправить событие Socket.IO. Пропуск любого шага рассинхронизирует вкладки.

## Компоненты

- библиотека Mantine, тема в `src/theme.ts`, стили в CSS-модуле рядом с компонентом
- файлы и папки в кебаб-кейсе, как в существующем коде (`label-picker.tsx`, `page-header/`)
- формы на Mantine Form со схемой Zod через `mantine-form-zod-resolver`
- любой видимый пользователю текст через `useTranslation`, см. скил `i18n`
- переиспользовать существующие компоненты из `src/components/{ui,common,layouts}`

## Маршруты

Карта маршрутов в `src/App.tsx`. Страницы подключаются через `React.lazy`, общая граница `Suspense` одна на все маршруты, layout и инфраструктура маршрутизации остаются загружаемыми сразу.

Тяжелые части содержимого откладываются отдельно уже внутри страницы, после того как данные разрешились: полный редактор, история страницы, редактор только для чтения. Читатель без прав на правку и без встроенных комментариев получает вариант только для чтения и не поднимает соединение коллаборации. Это сделано намеренно, при правке страниц такое разделение не ломать.

## Переменные окружения

Клиент читает конфигурацию только через `src/lib/config.ts`. Новая переменная требует правки трех мест: `.env.example`, блок `define` в `apps/client/vite.config.ts`, функция-геттер в `config.ts`.

## Проверка

```
pnpm --filter client build     # tsc затем сборка
pnpm --filter client lint
pnpm --filter client test -- <путь>
```

Клиент не форматируется автоматически после правки, потому что своего `.prettierrc` у него нет и единого стиля кавычек в коде тоже нет. Массовый `pnpm --filter client format` без запроса не запускать, он даст шумный дифф.

После правок интерфейса открыть страницу в браузере и прокликать сценарий. Typecheck проверяет код, а не работоспособность экрана.

## Антипаттерны

- `api.post` внутри компонента
- мутация без инвалидации кеша
- жестко зашитый текст в компоненте, где рядом уже есть `useTranslation`
- новый подход к стилям вместо Mantine и CSS-модулей
- передача сторов через пропсы
- «универсальный» компонент с десятком булевых флагов вместо двух отдельных
- обновление дерева страниц только локально, без REST и без события
